# Places, Keyed Values and Geometry (B6) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** `hex()` and `distance(a, b)` in formulas; properties keyed by a table row, a turn (past turns dropped) or a hex (place values on the Global holder) with `keyed()` reads and keyed output writes; a Ledger Places tab, a keyed-values panel and place text on map hover; one resolver for a Remove output's map.

**Architecture:** Vassal gains `BoardCells` (per-board name → cell index, cell distance). Rules gains `PropertyDef.KeyedBy`, `FormulaOutput.Key`, `KeyedFacts`, `MapRefs`, three functions and validator checks (with a module-aware overload). Core stores keyed values in `GameState.Keyed`, written by `LedgerDelta.ValueKey`, read by every evaluation context, dropped by `DropPastTurns`, filtered by `PlayerView`. Render drops past turns on phase entry, adds the keyed edit port/intent, the Places/keyed models and map status text. Desktop shows the Places tab, keyed panel and hover tooltip; Workbench columns; docs.

**Tech Stack:** C# .NET 10, Avalonia (Desktop), xUnit.

**Spec:** `docs/superpowers/specs/2026-11-26-b6-places-design.md`

## Global Constraints

Read `.superpowers/sdd/2026-11-26-b6-places/global-constraints.md` (git-ignored; same folder as the ledger) before each task. It holds the invariants and **every exact validator, run-time, log, Ledger, map and Workbench string**; use them verbatim. In short:
- Public repo: invented data only (Riverland). No content from any published game. Old packs keep bytes + SHA-256, `CurrentFormat` 4. Old saves keep bytes.
- Additive API only: new record members as body init properties; `IEvalContext.Hex/Distance/Keyed` and `IActionPort.EditKeyed` are default methods; new overloads, never changed signatures.
- Hidden information: place values follow "no side, Public unless Private"; `PlayerView` filters `GameState.Keyed` as `Ledgers`; `keyed()` on a view throws `HiddenData` when the value may be hidden; the status bar and tooltip read the viewer's state; the host checks every `KeyedEditIntent`.
- Packs without keyed properties pay nothing: `KeyedFacts.IsKeyed` is a null check first; `BoardCells` builds nothing until a hex name is resolved.
- Parallel batch B5: add to shared files (`Parser`, `Evaluator`, `IEvalContext`, `RulesValidator`, `RulesPackIo.Normalise`, `PhaseController`, wiki lists, RESUME) only in self-contained blocks as the spec's "Parallel batch" section says; do not edit `PhaseDefs.cs`, `Sequencer.cs`, `Phases.cs`.
- `-c Release`, one test project at a time, headless only, never stash/push, repo-local identity, `Co-Authored-By: Claude <Model> 5.5 <noreply@anthropic.com>`.

## Review Focus

1. **Old packs and saves keep bytes**: a hand-written pre-B6 `pack.json` literal (properties with labels/holders/resetAt, outputs with toMapId) loads and saves byte-equal with a constant SHA-256 (Task 2 `B6_absent_fields_keep_bytes`); a pre-B6 save literal with ledgers, history and a `ledgerDelta` command round-trips byte-equal (Task 3 `Save_without_keyed_keeps_bytes`).
2. **No leak**: a guest's view of a Private place has no value, no history entry, a redacted log line and no status/tooltip text; a Public place shows to every side; `keyed()` on another side's piece in a view is `HiddenData` (Tasks 3, 4, 5).
3. **Keyed and unkeyed never mix**: a keyed write never lands in `Ledgers`; a binding or filter reading a keyed property fails with the exact text; a mixed-version guest's unkeyed `LedgerEditIntent` on a keyed property is refused (Tasks 3, 4).
4. **Turn keys drop once, undoably**: entering turn 3 drops keys 1-2 of turn-keyed properties in the same Next Phase action; one Undo restores them (Task 4 `Turn_keys_dropped_on_entry_and_undo`).
5. **One map resolver**: a ToMapId given as a map name, or an id with spaces, validates exactly when it runs (Tasks 2, 3).
