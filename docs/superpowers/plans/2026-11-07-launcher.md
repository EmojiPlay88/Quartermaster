# Launcher (offline) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A VASSAL-style front door: a module list with a rules pack per module, Play offline (Continue, recent saves, New game, Open saved game), one shared new-game setup, and a launcher ↔ game-window loop.

**Architecture:**
- **Vassal** gains a cheap `ModuleInfo` reader (title/version from the module's metadata entry, no full parse).
- **Render** gains the UI-free launcher models: module library (paths, cached SHA, title, last played), recent saves per module, Continue lookup, new-game request + validation; new Settings fields.
- **App** gains `LauncherForm` and `PlayOfflineForm`, reuses the setup dialog as the shared New game setup, and `Program.Main` loops launcher → `MainForm` → launcher.

**Tech Stack:** .NET 10, C#, WinForms, xUnit (existing).

**Spec:** `docs/superpowers/specs/2026-11-07-launcher-design.md` (binding) — this plan covers §3.1, §3.2, §3.4 (offline fields), §4a items 1, 3, 4, 5, 6, §6 step 1. Online lobby (§3.3, §4) is 6b.

## Global Constraints

- **Content boundary (hard):** no real-game content; tests use synthetic modules from the test fixtures.
- **Direct ways in keep working:** command-line module paths, `--setup`/`--new`, every smoke flag, File → Open Module — all skip or bypass the launcher exactly as today.
- **Modules identified by SHA-256**; the library caches the SHA with file size and last-write time and re-hashes only when they change. Rules pack per module = existing `RulesMemory` (keyed by SHA).
- **Settings:** `ReopenLastModule` is reinterpreted as "Select the last module in the launcher" (default **true** for new settings; existing stored values are respected) — it never skips the launcher. New fields: `Modules` (list of `ModuleEntry`), `RecentSaves` (per module SHA, newest first, max 10).
- **Exact copy:** launcher window title `Quartermaster`; buttons `Add module…`, `Remove`, `Online lobby ▶`, `Play offline ▶`; greyed Online lobby tooltip `Online play arrives with the online update.`; missing file suffix `(file not found)`; Play offline buttons `Continue`, `New game…`, `Open saved game…`; Continue line `Continue: autosave {time} (turn {n}, {phase})` (phase omitted when none); menu `File → Back to launcher`; rules pack line `Rules pack: {file name}` or `Rules pack: (none)` with link `change…`; setting text `Select the last module in the launcher`.
- **Window lifecycle:** `Program.Main` loops: launcher → `MainForm` → if the game window closed via **Back to launcher**, show the launcher again; closing with the close box (or Exit) ends the app. Unsaved-changes prompt as today on both paths.
- **Never crash** on missing/corrupt module files, unreadable metadata, missing saves or autosave folders — greyed rows, messages, never exceptions to the user.
- **Look:** classic gray (Tahoma 8.25pt, system colours, DPI-aware), as in the accepted mockups.
- **Build:** `TreatWarningsAsErrors`; warning-free except the known MSB3277; `dotnet test Quartermaster.slnx` green after every task.
- **Test isolation / smokes:** never touch the real `%LOCALAPPDATA%` (`QUARTERMASTER_LAYOUT_ROOT` for smokes); smokes pass `--smoke N`; screenshots only in scratch.
- **Commits:** end with a blank line then `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`; noreply identity; never stage `startapp.cmd`.

## Review Focus

1. **A module file replaced by a new version** (same path, new SHA): the library re-hashes, the rules pack and Continue follow the new SHA, old recent saves still listed by path. Task 1 test `ModuleReplaced_RehashesAndMovesContinue`.
2. **Missing or locked module file / unreadable metadata**: the row shows `(file not found)` or falls back to the file name; selecting it disables Play buttons with a message; nothing throws. Task 1 tests `MissingFile_Greyed`, `BadMetadata_FallsBackToFileName`.
3. **Back to launcher with unsaved changes**: the prompt appears; Cancel stays in the game; after returning, the launcher shows the module just played as selected and "last played" updated. Task 3 test (model level) `ReturnToLauncher_UpdatesLastPlayed`.
4. **Startup paths**: command-line module path, `--setup`, smoke flags and `ReopenLastModule` set to false/true all behave as specified (launcher shown only without a module argument). Task 3 test `StartupDecision_Table`.
5. **Hashing large modules** (hundreds of MB): the launcher stays responsive — hashing runs off the UI thread and rows fill in when ready. Task 4 manual/smoke check; Task 1 test `Library_HashesOffThread_ReportsProgress`.

### Task 1: Module info and the launcher models

**Files:** Create `src/Quartermaster.Vassal/ModuleInfo.cs`, `src/Quartermaster.Render/Launcher/ModuleLibrary.cs`, `RecentGames.cs`; modify `Settings.cs`, `SettingsStore.cs`. Tests `tests/Quartermaster.Vassal.Tests/ModuleInfoTests.cs`, `tests/Quartermaster.Render.Tests/LauncherTests.cs`.

**Interfaces — produces:**
- `public sealed record ModuleInfo(string Title, string Version) { public static ModuleInfo Read(string vmodPath); }` — reads the module's metadata entry (`moduledata`; fall back to the build file's root `name`/`version` attributes only if `moduledata` is missing and the build file is small enough to read its first element without a full parse — builder's call), falls back to `(fileNameWithoutExtension, "")`; never throws.
- `public sealed record ModuleEntry(string Path, string? Sha256, long Size, DateTime LastWriteUtc, string Title, string Version, DateTimeOffset? LastPlayed);`
- `public sealed class ModuleLibrary(SettingsStore store)` — `IReadOnlyList<ModuleRow> Rows`; `ModuleRow(ModuleEntry Entry, bool Missing)`; `Add(string path)`; `Remove(string path)` (list only); `Task RefreshAsync(IProgress<ModuleRow>?, CancellationToken)` (re-hash only when size/mtime changed; runs off the UI thread); `MarkPlayed(string path, DateTimeOffset when)`; `string? RulesPackFor(ModuleEntry)` / `SetRulesPack(ModuleEntry, string? path)` (via `RulesMemory`, keyed by SHA); rows sorted by last played desc, then title.
- `public sealed class RecentGames(SettingsStore store, string layoutRoot)` — `Add(string sha, string savePath)` (dedupe, newest first, max 10); `IReadOnlyList<RecentSave> For(string sha)` (`RecentSave(string Path, bool Missing, DateTimeOffset LastWrite)`); `ContinueInfo? Continue(string sha)` = newest autosave under `<layoutRoot>/autosave/<sha>/` with turn and phase read from the save (`ContinueInfo(string Path, DateTimeOffset At, int Turn, string? Phase)`; read cheaply — snapshot `Turn` only; tolerate failures by returning the file with turn 0).
- Settings: `Modules : IReadOnlyList<ModuleEntry>`, `RecentSaves : IReadOnlyDictionary<string, IReadOnlyList<string>>`; `ReopenLastModule` default **true** for fresh settings.
