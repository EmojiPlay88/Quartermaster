# Cross-platform Port — Stage 3a (Ledger, Outliner, Overview, Inventory, Notes, Diagnostics, map export) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Bring the stage-3 tools except PDF/search/OCR (stage 3b) to the Avalonia app (`src/Quartermaster.Desktop`): the Ledger window with tabs, counter pictures, preview, manual edits, CSV export, Edit tabs and Show in Ledger; the Outliner dock; the Overview window; Inventory and Notes; Diagnostics; saving the map as a picture; and counter pictures in the batch grid — each behaving like the WinForms app.

**Architecture:** Same pattern as 2a/2b. UI-free logic still in WinForms files moves to `src/Quartermaster.Render` first (Tasks 1–2) and WinForms calls it with unchanged behaviour. Task 3 adds the shared Desktop pieces (counter thumbnail cache, preview popup, MapView accessors, batch-grid pictures). Desktop windows (Tasks 4–8) build on Render models that already exist (`LedgerTabs`, `LedgerBreakdown`, `LedgerJump`, `LedgerTabStore`, `LedgerTabsEdit`, `CounterImages`, `OutlinerModel`, `InventoryQuery`, `NotesSync`, `MapImageExporter`, `DiagnosticLog`, `PanelDockState`, `FloatPanelWindow`/`PanelFloat`), tested headless.

**Execution waves (parallel worktrees, as the user asked):** W1 {T1, T2, T3}; W2 {T4, T6, T7, T8}; W3 {T5}; W4 {T9}; then final review. Tasks in one wave touch disjoint files except the shared ones listed in Global Constraints.

**Tech Stack:** C# .NET 10, Avalonia 12.1.5 (SkiaSharp 4.154.0), Avalonia.Headless.XUnit, xUnit 2.9.3, GitHub Actions cross-platform CI.

**Spec:** `docs/superpowers/specs/2026-11-08-cross-platform-design.md`; stage list `docs/port/parity.md` (stage-3 rows ~104-114, 172-173, 191, 198-199, 201; notes ~37-38, 53, 56, 132, 148, 163, 169-170, 188).

## Global Constraints

- All Global Constraints of `docs/superpowers/plans/2026-11-09-port-stage2b-phases-formulas.md` apply (WinForms unchanged except calls into moved code + off-screen smokes `--smoke 3`, `--screenshot-breakdown --smoke 3`, `--screenshot-outliner --smoke 3` exit 0; Desktop free of WinForms/WinRT/P/Invoke/App/Ocr; labels/punctuation exactly as WinForms; ShortcutGestures/CommandRouter, Cmd on Mac; hidden information only through `ModuleSession.View`/`CanSee`/`VisibleOnly`; headless only, never visible windows; MacFlag collection for IsMac and for any test touching static window registries; no real-game content; noreply commits with both trailers; never push; parity rows updated per task).
- Desktop tests write nothing outside temp: `TestDataRoot` already points `QUARTERMASTER_LAYOUT_ROOT` at a per-process temp folder; ledger prefs/tabs go through `LedgerTabStore` with `AppDataRoot.Path`.
- Counter pictures come only from `ModuleSession.View.Pieces` via `ModuleSession.Counters.Render`; holder and group rows have none. Rendering off the UI thread, results posted with `Dispatcher.UIThread.Post`; shown bitmaps are never disposed while visible.
- Floating windows: owned Avalonia windows via `PanelFloat`/`FloatPanelWindow`; bounds under WinForms keys ("outliner", "doc:overview", "doc:ledger", "diag"), clamped with `ScreenFit` over primary-first screens; reopening docked is fine (matches WinForms).
- Shared files edited by several tasks of one wave (keep hunks small, appended, localized): `MainWindow.axaml(.cs)` (menu items, toolbar buttons — put wiring in new partials `MainWindow.Ledger.cs`, `.Outliner.cs`, `.Tools.cs`, `.Export.cs`), `Shell/Dialogs.cs` + `FakeDialogs` + `Program.QuietDialogs`, `docs/port/parity.md`.
- Out of scope (stage 3b or later): PDF rulebook viewer, chart windows, rulebook search, scans/OCR, Rule ref buttons (stay disabled); module-tree chart/PDF nodes keep "Opens in a later version".

## Review Focus

1. Hidden information in the Ledger, Outliner and Inventory for a hot-seat viewer limited to one side: no other side's private values, pictures, rows on hidden maps, or breakdown lines; Show in Ledger on a counter the viewer can't see gives the WinForms "has no row" message → `Ledger_hides_other_side_private_values`, `Ledger_pictures_only_for_visible_pieces` (T4), `Show_in_ledger_for_hidden_counter_says_no_row` (T5), `Outliner_viewer_sees_only_own_values` (T6), `Inventory_counts_only_visible_pieces` (T7).
2. Manual ledger edit typed with the user's locale (comma decimal, e.g. `2,5` on a German Mac) and invalid text: parsed invariant first then current culture exactly as WinForms `ParseNumber`; `'{text}' is not a number.` otherwise; unchanged value writes no history; required note → `Manual_edit_parses_comma_decimal_in_de_DE`, `Manual_edit_unchanged_writes_nothing` (T1/T4).
3. Large games: Ledger with 1,200 units and pictures on must stay responsive (virtualised rows, pictures rendered lazily for visible rows first, cap like WinForms 600 cached) → `Ledger_1200_units_reload_under_2s` (T4).
4. Whole-map export of a big map: runs off the UI thread with progress and Cancel, cancelling on window close, OOM gives the WinForms message, only one export at a time, file written atomically → `Export_whole_map_cancel_leaves_no_file`, `Second_export_refused_while_running` (T8).
5. Notes typed and then the game closed/replaced or the app quit within the 1 s debounce: text is committed (WinForms `FlushNotes` before replace/close) → `Notes_flushed_on_close_and_module_change` (T7).
